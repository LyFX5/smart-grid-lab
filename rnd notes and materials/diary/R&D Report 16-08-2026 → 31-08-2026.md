## 4. End-to-End Experiment (28-08, `experiment.ipynb`)

A complete closed-loop simulation was run:
1. Configure time/location (Amsterdam), load PV/load datasets.
2. Wrap into OpenSTEF `TimeSeriesDataset`.
3. Configure components (battery, H2, grid) + setup.
4. **Load persisted forecasters from MLflow** (PV + load, no retraining).
5. **Test inference** — point forecasts at decision time.
6. Build `ForecastsInformedRulesBased` controller.
7. **Run simulation**, then plot microgrid telemetry (PV, load, battery, grid/electrolyser) and display a metrics table.

## 5. Quantitative Results (MLflow runs)

**Direct PV** (`pv_gblinear`, trained 24-08):
- val P50 R² = **0.80**, full P50 R² = **0.74**
- P10/P90 calibration (observed-probability): full 0.13 / 0.51; val 0.12 / 0.63

**Two-stage GHI model** (`pv_gblinear_ghi`, trained 29-08): notably stronger
- val P50 R² = **0.88**, full P50 R² = **0.90**
- P90 R² = **0.93**; GHI R² consistently 0.83–0.95 across quantiles

→ The two-stage approach shows materially better R² and is the recommended path (matches the code comment: *"two-stage is site-agnostic and recommended for smart-grid-lab"*).

Load GBLinear model also trained and persisted (18-08).

## 6. Decisions & Community-Facing Judgments (from diary/decisions log)

- **RTC-Tools / metrics-calculator**: integration judged not useful for the EMS; native implementation preferred (relevant to the community's earlier RTC-Tools suggestion).
- **Two-stage PV** chosen as recommended site-agnostic forecasting method.
- **MLflow as the single model registry** bridging training notebooks → live inference adapters (no retraining in simulation).
- Use-case suite formalized: `PV-BATTERY-LOAD-GRID` (on-grid, minimize grid import/cycling/curtailment), `BATTERY-H2-FORECASTS`, `UC-OFF-GRID-H2-FORECAST-CONTROL`, and **peak-shaving** (planned).
